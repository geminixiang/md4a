# Releases

Pushing a `v*` tag runs `.github/workflows/release.yml`, tests the shared core, builds each native application through the same Task commands used locally, creates SHA-256 checksums, and publishes a GitHub Release. CI remains responsible for provisioning system toolchains and uploading/publishing outputs; packaging logic lives in `tools/dev.sh` and `tools/dev.ps1`.

## Local packages

Install [Task](https://taskfile.dev/) as documented in the root README, then run the platform command on its supported host:

```sh
task core:build
task macos:build VERSION=0.2.0 BUILD_NUMBER=42
task ios:build VERSION=0.2.0 BUILD_NUMBER=42
task android:build VERSION=0.2.0 BUILD_NUMBER=42 # local debug APK only
# With production signing environment configured:
task android:release VERSION=0.2.0 BUILD_NUMBER=42
task linux:build VERSION=0.2.0 BUILD_NUMBER=42
# Developer PowerShell on Windows:
task windows:build VERSION=0.2.0 BUILD_NUMBER=42
```

`VERSION` defaults to `0.0.0-dev`, and `BUILD_NUMBER` defaults to `1`. Outputs are placed in `out/artifacts`, with intermediates in `out/build/<platform>` and `out/stage/<platform>`. `core:build` runs tests but intentionally creates no misleading distributable package. Platform READMEs retain native commands for use when Task is unavailable.

Local-only artifacts additionally include `md4a-VERSION-ios-simulator-unsigned.zip` and `md4a-VERSION-android-debug.apk`. The iOS zip runs only in Simulator. The Android debug APK uses a development key. Neither is uploaded to a product GitHub Release.

## Published artifacts

| Artifact | Contents | Signing state |
| --- | --- | --- |
| `md4a-VERSION-macos-universal-unsigned.zip` | Native universal macOS `.app` | Unsigned; local/testing use |
| `md4a-VERSION-android.apk` | Universal Android APK for controlled direct testing | Production upload-key signed; signer digest verified in CI |
| `md4a-VERSION-android.aab` | Android App Bundle for Play Console | Production upload-key signed; Play App Signing re-signs delivered APKs |
| `md4a-VERSION-windows-x64-setup-unsigned.exe` or `*-setup-signed.exe` | Small Windows web installer; downloads official Windows App Runtime/WebView2 prerequisites only when missing | Filename and Authenticode state are explicit; production uses protected signing |
| `md4a-VERSION-windows-x64-unpackaged.zip` | Diagnostic unpackaged WinUI files | Unsigned; Windows App SDK runtime required |
| `md4a-VERSION-linux-HOST-ARCH.tar.gz` | Native GTK binary, README, and license for the actual build host | Unsigned; host GTK/WebKitGTK libraries required |
| `SHA256SUMS.txt` | Artifact SHA-256 hashes | Generated by the release job |

There is intentionally no iOS release artifact. An installable IPA requires an Apple Distribution certificate, provisioning profile, bundle signing, and App Store/TestFlight delivery. CI builds the unsigned iOS Simulator zip only as a local-package check and does not upload it. The Android debug APK is likewise not uploaded.

## Create a release

```sh
git tag -a v0.1.0 -m "v0.1.0"
git push origin main v0.1.0
```

Use **Actions → Release → Run workflow** to test packaging without publishing a GitHub Release.

Production Apple delivery is deliberately separated into manual, protected workflows. See [`testflight.md`](testflight.md) for iPhone/iPad and [`macos-signing.md`](macos-signing.md) for Developer ID signing/notarization. Neither workflow runs for pushes or tags.

## Production signing

Production distribution requires platform-specific protected secrets and signing steps. Android is configured now: the release job uses the protected `android-production` GitHub Environment, builds only upload-key-signed APK/AAB artifacts, verifies the signer SHA-256, performs an emulator install/launch/reinstall smoke test, and deletes temporary key material. It never publishes debug or unsigned Android artifacts.

Configure the environment secrets exactly as documented in [`platform/android/README.md`](../platform/android/README.md). Enable Play App Signing for `app.md4a`; preserve the upload key securely, register its certificate in Play Console, and upload the generated AAB to an internal testing track before production. GitHub secrets hold only the base64 keystore and its passwords; credentials must never be committed.

Remaining production work by platform:

- Apple Developer ID signing and notarization for macOS;
- Windows Authenticode in the protected `windows-production` environment;
- repository-native packages or Flatpak signing for Linux. Linux does not have a universal application-signing mechanism: Flatpak distribution should sign the repository/commits with its GPG key, while `.deb`/`.rpm` delivery should follow the target distribution repository's metadata and package-signing policy. The current host-specific tarball is intentionally described as unsigned.

Linux installers must not edit `mimeapps.list` or silently claim file defaults. The installed desktop entry advertises only Markdown MIME types; md4a requests explicit consent at runtime before invoking `xdg-mime`, and offers the action again from its File menu.

For Windows, configure `MD4A_WINDOWS_SIGNING_CERTIFICATE_BASE64` plus `MD4A_WINDOWS_SIGNING_PASSWORD`, or provision a certificate/cloud-signing agent and set `MD4A_WINDOWS_SIGNING_SHA1`. `MD4A_WINDOWS_TIMESTAMP_URL` is optional. CI signs and verifies both the app EXE and setup, checks the setup remains below 5 MiB, and runs install → launch/window-survival → uninstall. Unsigned local artifacts are labelled `unsigned` in their filename.

Do not commit certificates, provisioning profiles, keystores, passwords, or signing tokens.
