# Releases

Pushing a `v*` tag runs `.github/workflows/release.yml`, tests the shared core, builds each native application, creates SHA-256 checksums, and publishes a GitHub Release.

## Artifacts

| Artifact | Contents | Signing state |
| --- | --- | --- |
| `md4a-VERSION-macos-universal-unsigned.zip` | Native universal macOS `.app` | Unsigned; local/testing use |
| `md4a-VERSION-android-unsigned.apk` / `.aab` | Android release outputs | Unsigned; sign before distribution |
| `md4a-VERSION-windows-x64-unpackaged.zip` | Unpackaged WinUI executable and dependencies | Unsigned; Windows App SDK runtime required |
| `md4a-VERSION-linux-ubuntu24.04-x86_64.tar.gz` | Ubuntu 24.04 GTK application binary | Unsigned; system GTK/WebKitGTK libraries required |
| `SHA256SUMS.txt` | Artifact SHA-256 hashes | Generated by the release job |

There is intentionally no iOS release artifact. An installable IPA requires an Apple Distribution certificate, provisioning profile, bundle signing, and App Store/TestFlight delivery. The workflow only verifies that the iOS Simulator target builds during normal development; it does not label a simulator build as a release package.

## Create a release

```sh
git tag -a v0.1.0 -m "v0.1.0"
git push origin main v0.1.0
```

Use **Actions → Release → Run workflow** to test packaging without publishing a GitHub Release.

## Production signing

Production distribution should add platform-specific protected secrets and signing steps:

- Apple Developer ID signing and notarization for macOS;
- Android keystore signing, preferably publishing an AAB to Google Play;
- Authenticode and MSIX packaging for Windows;
- repository-native packages or Flatpak signing for Linux.

Do not commit certificates, provisioning profiles, keystores, passwords, or signing tokens.
